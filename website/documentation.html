Getting started

Install from the Download page (or run from source with npm run dev). Open Your AI (Run) in the sidebar to confirm Ollama is reachable or llama-server is configured, pick a model, then use Start. The header shows whether the runtime is on; you can click the status to open Run.

Main window & appearance

The app uses a dark, glass-style layout. Settings → Appearance offers accent presets (violet, teal, amber, rose, sky) that recolor buttons, highlights, and chart lines together.

Sidebar entries open slide-over drawers: Models (title in the drawer: Browse models), Your AI (Run), Training, Metrics, and Settings. On small windows the nav may dock to the bottom; chat and knowledge panels can slide from edges you choose (stored per window).

Inference runtime

The top bar selects how models are loaded (independent of which drawer you have open):

  • Ollama — uses your local Ollama API (default http://127.0.0.1:11434). Enter a model tag you have pulled (e.g. llama3.2). Override the base URL in Settings if needed.
  • Files on my PC — runs llama.cpp llama-server against a file path. Point Settings at the llama-server binary if it is not auto-detected, set the HTTP port if 8080 is busy, then choose a .gguf path (or .safetensors with conversion configured — see below).

Models (Hub) & downloads

Open Models in the sidebar. You can switch Recommended vs search, open the Browse / installed views, sort and filter cards, and expand rows for details. The primary Download action:

  • Prefers a main .gguf file when the repository lists one (skipping common auxiliary blobs such as vision projector files when possible).
  • Otherwise downloads a primary .safetensors weight together with listed config, tokenizer, and related small files, and with other parts of the same sharded set (…-01-of-04…) when applicable.
  • Stores everything under your models directory inside a per-repo folder that keeps Hugging Face relative paths (so config.json and weights stay in a valid tree).
  • With Ollama selected in the top bar, some curated repos map to an Ollama library name and use ollama pull instead of a file download when there is no suitable GGUF/Safetensors file in the listing.

Progress appears in the Models drawer and can be mirrored in a pinned Downloads widget (Settings). Completed downloads register for “installed” detection. Interrupted downloads can resume after restart when the app recorded the Hub file path. Add a Hugging Face token in Settings for gated models or better rate limits.

Safetensors & GGUF conversion

llama-server expects GGUF for inference. If you only have Safetensors checkpoints on disk, the app can run a one-time conversion using llama.cpp’s convert_hf_to_gguf.py (and Python) when those paths are set under Settings → AI engine. Ensure your layout includes config.json next to the weights—Hub installs arranged as above are intended to satisfy that. Very custom or partial repos may still need a full manual clone from the Hub.

Knowledge, wiki & chat

Ingest documents, notes, or saved chats into the knowledge base. The app chunks text, searches it at query time, and can compile wiki pages with glossary blocks, cross-links, and a knowledge graph (sampled on large libraries for performance).

Wiki-linked terms can appear as highlights inside assistant messages; hover for a short excerpt and open the wiki article from there. Optional auto-extract notes after each reply (Settings → Chat generation) runs an extra local completion to distill bullets into knowledge—disable it to save tokens.

Metrics & pinned widgets

Metrics shows time-series charts (process RSS, CPU, optional NVIDIA memory, runtime tokens, context, rolling prompt→reply latency, etc.). You can pin a compact metrics block, a downloads strip, and an activity (token throughput) visualization to any dock edge, adjust refresh interval and layout weights in Settings, and resize the pinned strip.

Training

The Training drawer starts an optional local Python LoRA workflow when configured. Keep dataset and base model paths readable by the app; see the repository training/ folder for scripts and dependencies. The shipped stub is minimal until you extend it with a real PyTorch / PEFT stack.

Settings & confirmations

Settings cover the models directory, llama binary and conversion script paths, Ollama URL, ports, max response tokens, Hugging Face token, IDE HTTP bridge, pinned widgets, color scheme, and maintenance actions.

Destructive actions (for example deleting models, clearing caches, or factory reset) use the system confirmation dialog so they appear above other UI.

Privacy, data & license

Chat history, knowledge, wiki, metrics samples, and download metadata live in a local SQLite database under app user data. Model files live in your chosen folder. Core inference does not require a cloud API; Hugging Face is contacted only for searches and downloads you start.
